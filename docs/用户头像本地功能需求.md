# 用户头像本地功能需求

相关入口：[阶段状态与决策记录](阶段状态与决策记录.md)、[阶段0行为对照矩阵](阶段0行为对照矩阵.md)、[用户头像本地功能UI设计](用户头像本地功能UI设计.md)（配套界面设计提案，待确认）

## 1. 背景与目标

WanAndroid 当前没有修改用户头像的服务端接口。首版在不上传头像、不修改服务端账号资料的前提下，允许已登录用户通过拍照或系统相册选择图片，经调整确认后作为当前账号在本设备上的头像。

该能力是用户明确批准的 Flutter 新增产品能力，不是 Android 固定提交 `78cdaade84ef24ebbe825041b499cbe1cd7ee286` 中已有的行为。Android 基线只有 56dp 默认人物头像，没有查看、拍照、选图或保存头像功能。

## 2. 已确认产品决定

1. 默认头像使用 Android 基线的人物图标，不保留 Flutter 当前的用户名首字展示。
2. 已登录且会话已验证的用户可修改头像；游客、会话恢复中或未验证状态不开放编辑流程。
3. 点击默认头像或已有自定义头像，都进入独立的“查看头像”页面。
4. 查看页右上角使用横向三点“更多”图标，点击后显示底部弹框。
5. 底部弹框固定只有“拍照”、“从手机相册选择”、“保存到手机”和“取消”四个选项；“取消”单独位于弹框底部。
6. 拍照或从相册选图后，必须进入头像调整页；只有用户点击“完成”且本地保存成功后才算修改生效。
7. 进入相机、相册或头像调整页后，只要最终没有确认新图片，当前头像就保持不变。
8. “保存到手机”保存的是查看页当前正在展示的头像图片，不是页面截图，也不是拍照原图。
9. 不提供“恢复默认头像”、“删除头像”或等价操作。自定义头像一旦生效，用户只能用新的拍照或相册图片替换，不能主动退回默认人物图标。
10. 头像仅保存在当前设备，不上传、不跨设备同步，也不作为服务端账号资料。

## 3. 页面与交互

### 3.1 个人中心头像入口

- 头像在个人中心账户区保持 56dp 显示尺寸。
- 无本地自定义头像时显示默认人物图标，不显示用户名首字。
- 已登录且会话已验证时，整个头像区域可点击，点击进入查看页。
- 游客及会话不可编辑状态只显示默认人物图标，不进入头像编辑流程。
- 点击区域不小于 48dp，读屏名称为“查看头像”。

### 3.2 查看头像页

- 使用独立全屏页面，深色背景上居中显示当前头像。
- 左上角提供返回；右上角提供横向三点“更多”。
- 自定义头像显示经用户确认后实际保存的方形头像图片；个人中心仍以圆形裁切显示。
- 支持双指缩放和拖动查看，双击恢复默认缩放比例。
- 页面底图、返回按钮、更多按钮不得被“保存到手机”一并写入图片。

### 3.3 底部操作弹框

点击横向三点后显示底部弹框，按以下顺序排列：

1. 拍照。
2. 从手机相册选择。
3. 保存到手机。
4. 取消。

“取消”与上方三项保持明显分隔。点击取消、点击遮罩区或使用系统返回，都只关闭弹框并留在查看头像页，不改变头像。

### 3.4 拍照

- 点击“拍照”后调用系统相机拍摄静态图片，不自建相机界面。
- 仅在用户主动选择“拍照”时请求必要权限，不在启动或进入个人中心时预先请求。
- 拍照成功后进入头像调整页；用户在系统相机中取消、拍摄失败或返回时，留在原头像查看页且当前头像不变。
- 拍照所得原始临时图片不自动加入系统相册；只有用户后续选择“保存到手机”才保存当前已生效头像。
- 只拍摄静态图片，不请求麦克风权限。

### 3.5 从手机相册选择

- 调用 Android/iOS 系统图片选择器，不开发自定义相册页。
- 仅允许单选静态图片，不允许视频。
- 应尽量只获得用户选中图片的临时访问权，不申请读取全部相册。
- 选择成功后进入头像调整页；取消选择、读取失败或返回时，留在原头像查看页且当前头像不变。

### 3.6 头像调整页

- 使用 1:1 方形裁切区和圆形头像遮罩预览。
- 支持拖动、双指缩放和旋转。
- 顶部提供“取消”、标题“调整头像”和“完成”。
- 点击“取消”或系统返回时，放弃本次临时图片，返回查看头像页，原头像不变。
- 点击“完成”后才进行解码、方向校正、裁切、去除隐私元数据和本地持久化。
- 处理与保存期间禁止重复提交，保留旧头像显示；保存成功后原子替换旧头像并返回查看页。
- 任何处理或保存失败都不得覆盖原头像。

### 3.7 保存到手机

- 保存查看页当前头像的图片内容，不包含黑色背景、顶栏、按钮或弹框。
- 当前为自定义头像时，保存已裁切并已生效的当前头像，不保存最初的拍摄/选择原图。
- 当前为默认头像时，保存查看页当前展示的默认人物头像图片。
- 保存到手机不改变当前应用头像。
- 成功后明确提示“头像已保存到相册”；权限被拒绝、空间不足或写入失败时明确提示，不误报成功。
- 重复保存不覆盖旧文件，文件名使用可区分的时间标识。

## 4. 本地数据与账号语义

- 头像以服务端稳定 `userId` 为键分账号保存，不使用昵称、用户名或 Cookie 作为文件身份。当前登录操作身份为 `userId + accountVersionKey`（不透明键，由现有会话存储产生，不含 Cookie 或凭据）；普通拍照、相册、调整和保存操作都必须捕获并校验该身份，退出、切号或重新登录后旧操作立即失效。Feature 层不得直接读取会话存储、Cookie 或原始代次。
- 退出登录后保留该账号本地头像；重新登录同一 `userId` 时恢复展示。
- 切换账号时必须立即切换到新账号对应的本地头像或默认头像，不得短暂显示前一账号头像。
- 打开相机、相册或处理图片时必须绑定发起时的账号代次；返回时如果已退出或换号，丢弃临时结果。
- 自定义头像文件保存到 App 私有目录，不保存相册原文件路径，不依赖临时 URI 的长期有效性。
- 头像作为本机非敏感个性化文件处理，但因其可能包含个人影像，应排除系统备份，不经备份迁移到其他设备。Android 应用已整体关闭备份（`allowBackup="false"`），不新增相互竞争的备份规则文件；iOS 头像目录通过最小原生能力设置排除备份标记。
- 清除 App 数据或卸载 App 后本地头像消失；这是本地数据生命周期，不是用户可用的“恢复默认头像”功能。
- 若本地图片文件意外丢失或损坏，应安全回退显示默认人物图标并保留脱敏诊断；这是故障容错，不是主动删除入口。

## 5. 图片处理规则

- 输入支持 Android/iOS 系统选择器可返回的常见静态图片，包括 JPEG、PNG 和可正常解码的 HEIC/HEIF。
- GIF 只按静态首帧处理，不保留动画；视频和不支持的文件类型拒绝并给出反馈。
- 处理时应正确应用图片方向信息，避免保存后旋转或镜像错误。
- 实际持久化的自定义头像是 1:1 方形静态图片，固定输出 `512×512 PNG`（处理管线使用 `dart:ui`，其编码格式仅有 PNG）；重绘并编码后不保留原图 EXIF、GPS、拍摄时间和设备型号。处理流程：外部返回的临时文件立即复制到应用临时目录 → 解码并验证尺寸 → 应用方向 → 按用户缩放/拖动/旋转参数重绘 → 1:1 裁切 → 编码 → 重新解码验证 → 原子提交。必须以带 EXIF 旋转与镜像信息的夹具验证双端方向归一。
- 重新编码时去除 GPS、拍摄时间、设备型号等 EXIF 隐私元数据。
- 新图片必须先完整写入并验证可解码，再原子切换当前索引；旧文件只能在新文件成功生效后清理。
- 超大、损坏或解码失败的图片不得覆盖当前头像。

## 6. 权限与平台边界

- Android/iOS 均优先使用系统相机和系统图片选择器，不申请与当前操作无关的广泛媒体访问权限。
- Android 拍照通过系统相机 Intent 完成，应用不声明、不申请 `CAMERA` 权限；没有可用相机时给出失败反馈并保持当前头像。
- iOS 配置清晰的相机使用说明（`NSCameraUsageDescription`，仅在选择"拍照"时由系统请求）、相册选择说明（`NSPhotoLibraryUsageDescription`，选择器以 `requestFullMetadata: false` 调用）和仅添加到相册的用途说明（`NSPhotoLibraryAddUsageDescription`，原生通道只申请 PhotoKit `.addOnly` 权限）。
- Android 选图优先 Photo Picker，不申请 `READ_MEDIA_IMAGES` 或完整相册读取权限；保存到相册：API 29+ 经 `MediaStore` 无需存储权限，API 24–28 使用 `maxSdkVersion=28` 的 `WRITE_EXTERNAL_STORAGE` 降级并在执行保存时申请；项目最低 API 24，旧系统降级路径单独验证。
- 权限首次拒绝时给出用途反馈；已永久拒绝时可引导前往系统设置，但不循环弹权限请求。
- 权限被拒绝、设备没有可用相机或相册/相机应用不可用时，保持当前头像并提供可理解反馈。

## 7. 竞争、恢复与失败原则

- 选择、拍照、图片处理、本地保存和保存到相册均不允许重复并发提交。
- 外部相机/相册返回后必须重新校验路由实例、会话账号与账号代次，过期结果不得落盘。
- Android 在系统相机/选择器期间可能回收进程：启动外部页面前持久化唯一 `PendingAvatarOperation`（操作 ID、`userId`、来源、创建时间、状态）；启动时经 `retrieveLostData()` 取回结果，且仅当存在唯一 pending 记录、当前为已验证登录、`userId` 一致、记录未超 24 小时且返回文件存在并可解码时，才恢复到调整页；账号不同、记录缺失、结果为空、超时或无法证明归属时删除临时文件并清除 pending，不修改头像。进程重启后操作身份必然变化，以"持久化 pending + 已验证同一 `userId`"重建归属。成功、取消、失败和主动丢弃后都必须清除 pending。
- Android 在外部相机或相册打开期间终止 Activity 后，若能安全恢复且账号仍匹配，则恢复到头像调整页；无法证明归属时丢弃结果，不写入当前头像。
- App 进入后台、页面销毁或用户返回后，迟到的图片处理结果不得导航、覆盖头像或显示过期成功提示。
- 任何失败默认保留旧头像；不允许用“先改 UI、失败再回滚”的乐观替换冒充成功。
- 错误文案不暴露本地绝对路径、相册 URI、图片元数据或平台异常堆栈。

## 8. 视觉、动态字体与无障碍

- 个人中心、头像查看页、底部弹框和头像调整页均需要支持四套配色、浅色/深色模式与 200% 字体。
- 系统相机和系统相册页保留平台自有外观与返回行为，不强行还原为 Android 页面。
- 所有操作触摸区域不小于平台建议尺寸，返回、更多、拍照、相册、保存和取消都需有明确读屏名称。
- 裁切圆形遮罩不能成为唯一状态提示；“取消”与“完成”必须可被读屏定位。
- 底部弹框打开时读屏焦点进入弹框，关闭后返回横向三点“更多”按钮。

## 9. 非目标

首版不包含：

- 服务端头像上传、下载或跨设备同步。
- 头像 URL、网络图片或社交账号头像导入。
- 游客头像编辑。
- 昵称、手机号或其他账号资料编辑。
- 视频头像、动态 GIF 头像或 Live Photo 头像。
- 自建相机或自建相册浏览器。
- 恢复默认头像、删除自定义头像或退出时自动清理头像。
- 自动把拍照原图保存到系统相册。

## 11. 实施前置与待验证范围

- 当前仓库没有图片选择、头像裁切或保存到系统相册的直接依赖。实施前需按阶段0锁定流程审核依赖身份、许可、Android API 24/iOS 15 兼容性与双端构建。
- 本文冻结产品行为，不预先冻结具体 Flutter 插件、编码库、文件后缀或平台实现类。
- 实施必须保持 View → ViewModel → Repository → Storage/Platform Gateway 方向，Feature View/ViewModel 不直接访问图片选择、文件系统、相册写入或权限插件。
- 实施后需运行阶段 5 完整自动入口，并增加 Android/iOS 的系统相机、系统相册、相册写入、权限拒绝、Activity/路由恢复和真机手势验证。
- 需求文档完成不代表生产代码已实现，也不关闭阶段 6 逐页视觉、无障碍、真实进程恢复或发布门禁。
