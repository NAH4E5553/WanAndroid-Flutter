## 3. Flutter 生产调用链与复用

| 层级 | 当前文件或计划落点 | 职责 |
|---|---|---|
| 原生资源 | Android `res/values/styles.xml`、`values-night/styles.xml`、两个 `launch_background.xml`，计划补充API31资源；iOS `LaunchScreen.storyboard`及LaunchImage资源 | 提供静态初始画面与系统版本适配 |
| 入口和组合根 | `lib/main.dart`、`lib/src/app/bootstrap/bootstrap.dart`、`lib/src/app/app.dart` | 启动现有依赖/路由，组装展示层；不能等待动画才初始化业务 |
| View | 计划 `lib/src/app/startup/` 内启动展示组件，经MaterialApp适当组合点接入 | 只渲染展示状态，发送首帧、动画和生命周期事件；必须实际接入主应用 |
| 展示控制 | 同目录最小状态控制器，实际命名由zcode回填 | 唯一启动展示状态源，负责幂等退出、取消与本次启动身份；不承担首页/会话业务 |
| 首页View与ViewModel | `features/home/view/home_screen.dart`、`view_model/home_view_model.dart` | 复用现有UiState与请求；将实际遮挡条件纳入展示测点资格 |
| Repository及DataSource | 现有ArticleRepository、主题/会话/头像权威 | 保持原调用链，不新增仅为启动动画服务的业务Repository |
| 诊断 | `core/diagnostics/startup_metrics.dart`、`tool/measure_android_startup.py` | 延续默认关闭且无敏感信息的测量，区分首帧与真正可见的首页 |

必须保持路由恢复、深链及头像恢复导航。不要为了播放动画而强制跳首页、重建Router或丢弃Router子树。不得通过将现有 `homeVisible` 设为false来解决遮挡埋点，因为它同时会暂停首页请求；启动层遮挡与业务前后台/路由可见性是不同事实，需明确组合条件。

## 4. 状态身份与并发

| 事实 | 唯一权威 | 身份与版本 | 持久化 |
|---|---|---|---|
| 启动层是否遮挡内容 | 单个应用启动展示控制器 | 当前启动展示实例及回调代次 | 无；不写偏好，不跨进程恢复片头 |
| 路由与前后台状态 | 现有路由/恢复与AppVisibility控制器 | 现有分支与页面身份 | 保持既有恢复契约 |
| 首页数据 | HomeViewModel和既有Repository | 现有数据代次与请求取消语义 | 保持现状 |
| 启动测点 | StartupMetrics | 本次main与当前有效帧 | 默认关闭，无上传 |

- 退出后不能因主题重建、重复回调、前后台切换或导航再次显示动画。
- 仅仍挂载且身份有效的动画/帧回调可提交状态；dispose后释放Ticker、监听器和计时器。
- 进入后台时终止或暂停动画，恢复后收敛为内容可用状态，不重新播放片头；具体实现须用测试证明。
- 失败、空数据和长时间无响应不能使启动层永久遮挡；正常退出应有界，且不依赖网络结果。
- 当前页面变更时只交出展示权，不干预账号、头像候选或路由栈；本任务无写入回滚或未知写入结果。
