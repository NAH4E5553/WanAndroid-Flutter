## 已接入的统计

- `STARTUP_METRICS`编译开关，默认关闭；仅输出`WAN_STARTUP`结构化本地日志，含时长、固定测点名和success/empty/error状态，不含账号、Cookie、URL或文章内容，不上传。
- `dart_main`、`binding_ready`、`dependencies_ready`、`run_app`：定位Dart入口与同步组装时间。
- `first_raster`、`home_first_raster`：实际Flutter首帧/首页帧，加载圈只计此处。
- `home_articles_raster`：文章首个终态；加载成功、空、错误分开。
- `home_terminal_raster`：首页首次终态；文章错误直接为错误，文章正常时等待问答结束。
- `home_content_raster`：文章和问答都成功结束时的首页内容帧；任一块为空标empty，错误不输出成功测点。

View仅发送当前UiState构建事件，ViewModel分类；诊断复用该状态，不建立第二业务事实源。提交帧时核对快照仍有效且可见，再匹配FrameTiming的buildStart/buildFinish，终点采用rasterFinish及rasterFinishWallTime。帧统计可能批量迟到，日志接收时间不是完成时间。首次终态后注销帧监听。空数据、失败、超时、旧快照、隐藏页、重复构建均不冒充成功。

这里“展示”止于栅格化完成，不证明物理屏幕扫描输出；不是调用Android `reportFullyDrawn`产生的系统TTFD。Dart起点不包括进程/原生引擎时间，必须与设备侧Launcher起点合并。

## 采样入口

本轮使用忽略目录`build/startup_guest_project`中的独立游客构建副本。创建规则：只复制本项目源码、平台源文件与锁文件；跳过`.git`、`.dart_tool`、`build`、`.gradle`、`local.properties`、`key.properties`、Keystore等；仅将applicationId改为`.startup`、名称改为“WanAndroid Flutter 启动测量”。构建前核对Dart源码与锁版本/校验值，首次安装前确认包不存在，禁止恢复备份或登录。副本不是另一套生产实现，所有生成物与样本均留忽略的build目录。

实际测量命令（安装包现已卸载，不能直接假定可重跑）：

```bash
# 在build/startup_guest_project构建已核对的独立游客副本
flutter build apk --profile --dart-define=STARTUP_METRICS=true
# 在项目根运行采样；原主应用不会被force-stop、启动或清理
python3 tool/measure_android_startup.py \
  --adb /Users/sn/Library/Android/sdk/platform-tools/adb \
  --device 6578b1b0 --package com.personal.wanandroid.flutter.startup \
  --label 'WanAndroid Flutter 启动测量' --desktop-page 第3屏 \
  --tap-x 160 --tap-y 1180 --count 5 --allow-real-network \
  --output build/startup_metrics_guest.json
```

`--allow-real-network`以本轮用户确认为依据。脚本只保存固定测点、状态与时间，未保存网络正文/请求头/原始logcat；原始微秒数据和源码身份清单位于忽略的build目录。第三页与坐标是本轮设备观察值，不能未经核对在其他布局复用。

冷启动逐次列首帧、文章、完整首页与成功/空/失败/超时；汇总有效样本数、中位、最小、最大。缺失测点保留缺失，不补零；五次样本不宣称稳定p95。初次安装后的首轮与后续force-stop轮次分列解释。热启动/设备重启不与force-stop冷启动混算。

## 优化判定

**判断：有针对性的首帧优化空间，目前不需要大规模重构启动流程。**首帧前阶段占输入到完整首页耗时的约64%～74%；同步依赖组装仅约1.7ms，没有证据表明它是瓶颈。优先进一步剖析系统START→Dart的约0.63秒，以及runApp→首帧约0.65秒，按实际UI/Raster和原生Trace决定改动；不能直接把后一段全部归因于Widget构建、着色器或网络。

Android vitals将冷启动TTID≥5秒视为过慢；本轮系统TTID为1.304～1.447秒，不属于该阈值下的过慢冷启动，但不等于项目已冻结性能阈值或发布验收通过。[官方定义](https://developer.android.com/google/play/vitals/launch-time)。完整首页1.808～2.234秒是自定义内容端点，不能拿它替代Android TTID。下一步建议专项追踪首次绘制与原生初始化；本轮只测量和判断，尚未实施启动优化。
方法参考：[Android启动时间](https://developer.android.com/topic/performance/issues/launch-time)、[Flutter性能分析](https://docs.flutter.dev/perf/ui-performance)。Android TTID/TTFD与此处的应用自定义内容端点分开；Profile设备证据不替代Release、逐页视觉或真机发布验收。

实现偏差：采样改为同生产源码的独立游客安装包，以消除原会话发送风险；已明确列出测量身份及不能外推的边界。埋点调用链和产品行为无偏差。未提交、未推送、未创建PR。
