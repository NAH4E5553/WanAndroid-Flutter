## 1. 已明确需求与本修订范围

## 2. 页面与交互规格

### 2.1 默认图片网格

- 全屏展示，不带宿主底部 Tab。新一轮进入默认“所有图片”，从顶部开始。
- 顶栏左侧关闭按钮，椭圆形分组按钮相对整个页面水平居中，右侧预留与左侧相等空间，避免标题偏移。
- 按钮最大宽度受父布局限制；长分组名省略，读屏仍读完整名称。最小点击区域 48dp；200% 字体下允许顶栏增高。
- 网格所有分组、横竖屏均固定四列。方形缩略图按 cover 居中裁切；默认间距 2dp。列宽由可用宽度计算，不由内容决定。
- “所有图片”首格为截图中的“拍摄照片”，计入四列布局、不计入图片数量；其他相册不重复插入拍照格。宿主未提供拍照能力时隐藏该格，不留空洞。
- 首版单选：点击照片开始准备所选文件，显示该格忙碌反馈并阻止重复选择。无需多选勾选框、发送按钮或单独预览页；成功后进入宿主现有裁切流程。
- 图片按§3.2的全局稳定顺序分页，不通过读取原图EXIF批量补齐时间。
- GIF/Live Photo按§5.1导出静态结果；不播放动画或视频。格式不支持、资源不可读取时反馈，不更新头像。

### 2.2 相册下拉与箭头

- 点击椭圆按钮，从顶栏下方展开覆盖层；网格不被挤压、不回滚顶部。
- 覆盖层宽度等于内容区宽度，高度最多占满顶栏以下安全区；分组过多时内部滚动，少量分组时内容下方保留可点击关闭的遮罩。
- 每行由方形封面、分组名称、数量和当前分组勾选标记组成。封面取最新可访问图片；“所有图片”首版同样用最新图片，暂不做拼贴。数量加载中显示占位，失败显示不可用，不伪装为 0。
- “所有图片”固定第一项，其余按§3.2的最新图片排序键排列，以分组ID稳定打破并列；数量为0的普通分组隐藏，“所有图片”始终保留。
- 同名相册不能合并，使用平台 ID 区分。若名称重复，显示平台可提供的简短来源提示；不得暴露完整文件路径或虚构来源。
- 点击不同分组：立即同步按钮名称及勾选项、收起面板、加载该组图片；未就绪时显示占位，不能把上一组照片挂在新标题下。点击当前分组仅关闭面板。
- 同一箭头由0°旋转至180°，默认200ms easeInOut，与面板展开进度同步；快速连续点击从当前进度反向，不创建第二个图标。系统减少动画设置开启时直接到目标状态。
- 面板展开时，底层图片不可点击、不可聚焦、不可被读屏访问；焦点进入当前相册行，关闭后回到分组按钮。隐藏面板不留下 Tooltip、命中区域或语义。
- 浏览状态的系统返回优先收起面板，再返回退出选择器；准备文件时返回取消本次准备并留在网格，详见§6.5。左上角关闭始终退出选择器。页面失去前台活动状态时收起面板。
- 每个相册的滚动位置只在本次选择会话内保留；首次切换到某组从顶部显示，切回恢复位置。相册内容或权限代次改变时优先按可见资源锚点恢复，锚点不存在时安全回退。

### 2.3 外观和无障碍

- 包默认提供截图风格的深色主题，同时支持ThemeData/专用主题参数注入浅深背景、文字、按钮、选中标记、分隔线及间距。宿主接入使用当前项目四套主题角色，不硬编码微信绿色。
- 所有图片网格保持四列，大字体不改变列数；拍照格文字允许换行，图标与文本适配小屏，不牺牲点击区域。
- 相册行可随字体增高；长名称与数量分开布局，确保数量、选中标记不被挤出。
- 为关闭、分组按钮（含展开/收起状态）、相册名称/数量/当前选择、图片位置、重试、管理权限提供读屏名称。不得把照片内容自动识别为读屏文字。
- 正确处理状态栏、底部安全区、横屏和返回手势；视觉对照使用虚构图片，真实相册截图不作为自动测试夹具。

### 2.4 权限和备用入口的位置

- 顶栏只放关闭和居中分组按钮；无可浏览权限时分组按钮禁用，不向顶栏追加权限操作。
- 完整授权：底部安全区上方固定一条次级操作栏“使用系统相册选择”；网格扣除操作栏高度，不遮最后一行。完整授权空库也保留该栏。
- 部分授权：顶栏下方固定提示条“仅显示已授权的照片”，右侧/换行后为“管理可访问照片”；底部保留系统选图。部分授权空列表中心说明“当前没有可访问的图片”，不另放重复管理按钮。
- 首次未授权、拒绝、受限：网格位置由说明页替代，中央放用途、对应主操作及系统选图按钮，隐藏底部重复入口。按钮规则见§4.4；失去读取权限时同样切换该页。
- 分组面板覆盖顶栏以下内容，展开时提示条、网格和底栏一起暂停命中/焦点/语义；收起后恢复。准备期间这些操作禁用，只保留进度、取消准备和关闭。
- 独立包的宿主未提供系统选图能力时不展示空按钮；WanAndroid必须提供。拒绝/空库时若宿主提供拍照，可在说明区显示“拍摄照片”，不为获取照片先申请整库权限。

## 3. 相册和“全部”的含义

- Android 分组来自系统媒体库的图片 bucket；iOS 分组来自 PhotoKit 相册/集合，不承诺为真实文件夹树，也不承诺与小米图库分组一一相同。
- “所有图片”按平台资源 ID 去重。同一资源可属于多个 iOS 相册，因此各组数量之和不一定等于总数；复制的两个资源即使画面相同也计两张。
- 所有图片、相册数量、封面和分页使用相同的图片类型过滤及权限范围。数量代表媒体库当前可见图片，不代表每张图片都一定能下载或解码。
- 部分授权仅统计可访问图片，界面持续显示“仅显示已授权的照片”；iOS/平台未暴露完整相册结构时，只显示实际可查询分组，不伪造缺失文件夹。
- 不扫描应用私有目录、私密/锁定空间、未索引文件或其他账号空间。Android 厂商云图库若未通过系统媒体 API 开放，不承诺读取。
- 保留次级“使用系统相册选择”入口，用于用户需要其他提供方时；该入口不改变主页面四列默认体验。

### 3.1 本期集合范围

| 平台 | 纳入 | 排除/身份规则 |
|---|---|---|
| Android API24–28 | 系统外部媒体图片集合实际暴露的普通共享存储照片 | bucket身份使用查询集合+bucket ID；不假设旧系统提供独立卷名 |
| Android API29+ | 当前用户已挂载且MediaStore可读的外部卷，包括主共享存储和已索引SD卡 | 资源以卷+媒体ID/规范content URI识别；分组以卷+bucket ID识别；不重复合并查询总视图与各卷；卷卸载视为库变化 |
| iOS | 所有可访问普通图片的虚拟“所有图片”；用户相册；智能相册仅收藏、屏幕快照 | 用户文件夹递归发现后将叶相册平铺；文件夹不额外生成总数，重名时用可用父级名称区分；以localIdentifier识别，不按名字合并 |
| iOS共享范围 | 系统正常图片查询公开的共享照片图库资源按同一权限纳入“所有图片” | 首版不单独浏览Shared Albums共享相簿集合，不申请额外账号；普通查询若已公开某资源，不猜测所有权也不重复计数 |

不纳入Android内置铃声/壁纸卷、未索引OTG/文件提供方；不枚举iOS隐藏/最近删除集合、厂商私密空间或系统未开放的集合。图库的“文件夹”不是文件系统扫描入口。过滤条件统一为平台标记的普通图片、当前可见且非待写入/回收站资源（相关字段按API可用性使用）；不预先读取每张原图检测格式。RAW等图片可能计数/有缩略图但选取时提示不支持，数量不是可导出数量承诺。

### 3.2 时间、数量与稳定分页

- Android主排序时间：正数拍摄时间优先，否则加入媒体库时间，否则修改时间，否则0。拍摄时间按毫秒，加入/修改按秒转为UTC毫秒；旧系统使用Images对应可用字段，不访问更高API才有的常量。iOS：有效creationDate，否则modificationDate，否则0；不伪造系统未公开的“加入时间”。导入旧照片仍按拍摄/创建时间优先，而非本次导入时刻。
- 时间倒序后，以规范资源ID按固定序（非本地化字符串比较）升序打破并列；Android包含卷身份。封面取该组第一张，普通相册按封面时间倒序、相册ID升序排列。无时间图片排在有效时间之后。
- 同一查询快照内，去重、过滤、全局排序在分页切片之前完成。原生查询能表达同一完整排序键时在查询层执行；否则Repository建立仅含ID/时间/相册归属的轻量元数据索引，再排序切页。禁止每页取出后各自排序或把多个卷的分页简单拼接。索引期间显示加载，可取消；不解码原图。
- 媒体变更、卷挂载变化和权限变化递增快照版本，停止旧分页、重建一致快照，再按资源锚点恢复；加载中显示数量占位。先前数量可带更新状态，不能与新版本照片混作已完成结果。索引内存和重建耗时纳入§7.1大图库测量。
- 原生通知缺失时，恢复前台及读取失败主动复核；不能保证屏外图库变更瞬时同步。资源被删/权限撤回必须在导出移交前再次校验。

## 4. 权限与生命周期

| 平台 | 读取图片的计划权限 | 行为 |
|---|---|---|
| Android API 24–32 | READ_EXTERNAL_STORAGE，maxSdkVersion=32 | 进入只检查；点击“授权照片访问”才申请；MI9/Android11重点实测 |
| Android API 33 | READ_MEDIA_IMAGES | 仅请求图片，不请求视频、音频 |
| Android API 34+ | READ_MEDIA_IMAGES + READ_MEDIA_VISUAL_USER_SELECTED | 正确区分完整/部分/拒绝，支持重新选择可访问图片 |
| iOS 15+ | NSPhotoLibraryUsageDescription；PhotoKit readWrite 授权级别 | API没有独立读取级别；组件实际只调用读取能力，处理完整/部分/拒绝/系统限制 |

- 权限事实以操作系统为准，不把曾经授予的布尔值永久保存；组件维护当前会话快照与权限代次，重新进入前台、管理权限返回、读取失败时复核。
- 进入选择器、启动App、进入个人中心和恢复前台均只检查。只有明确点击授权/管理才可触发对应系统弹层，不能把“打开选择器”当作申请动作。用途说明明确“展示相册和照片供你选择”，替换旧的“只访问已选图片”说明。
- 首次拒绝：展示用途、用户主动重试和系统选图入口；不可再次申请或受系统限制：按平台真实状态解释，可用时提供前往设置，不循环申请、不把每次拒绝都称为永久拒绝。
- 部分授权：仍可选图，提供“管理可访问照片”；没有授权图片时显示专门空状态，不误报手机没有照片。
- 权限收回/范围缩小：立即失效旧查询，先遮蔽旧图再按§5.2处理各层缓存；取消准备，重新检查范围。迟到结果不返回宿主；不能只清Dart映射却保留可复用原生图像。
- 图片被删除、相册消失：刷新对应事实；当前相册失效时回“所有图片”并提示。恢复前台复核媒体变化，不无条件重新定位至顶部。
- Android 相机权限与现有系统拍照实现一致；保存头像到手机仍走现有写入权限。组件不申请定位、媒体位置、麦克风或所有文件管理权限。
- 当前已确认自用或非 Google Play 分发，首版按此实现；不预建多渠道构建。Google Play 对偶发头像选图的广泛照片读取有政策限制，若以后需要 Play 版，须重新评估并明确采用系统选图策略，验证最终合并 Manifest 不含该用途不允许的广泛权限。运行时关闭入口或保留备用选择器不能替代发布要求。

### 4.1 系统版本支持与验证矩阵（2026-09-29补充）

### 4.3 实现策略与适配验收

- 分离三层：共享Flutter界面与状态；Android/iOS权限和媒体适配器；有实证才新增的厂商兼容补丁。包公开API不暴露ROM分支，宿主无需识别品牌。
- 依赖锁定前检查photo_manager、image_picker及其原生依赖的最低系统、编译SDK、Xcode/Swift/Gradle/Kotlin和原生库要求；不只依据pub.dev平台标签判断兼容。
- 不依赖Google Play Services读取本地媒体。系统备用选图先检测可用能力，再使用现有兼容路径；没有可用处理程序时给出错误，不强行绑定小米/微信等应用包名。
- 设置入口使用公开系统方式；打不开时显示平台适用的人工路径，不对厂商私有Activity做无依据硬编码。
- 当前开发门槛：官网要求映射到代码及固定Fake回归、包/宿主静态门禁、可用环境构建/集成、MI9/MI17设备专项。官网核查、Fake、模拟器和真机证据分列。
- vivo/OPPO/荣耀/三星真机及全系统矩阵明确后置，不采购、不安排、不将缺设备作为本轮开发阻断。已查官网不能描述为这些设备已通过。
- iOS执行可用构建与Simulator入口；真机、iCloud和完整历史系统覆盖后置，保留边界。不会因暂缺iOS真机把整个开发任务标为未完成。
- 每份证据记录组件版本/宿主提交、插件锁版本、型号、地区ROM、系统完整版本/API、安全补丁、target/compile SDK、权限初始状态、用例、结果与日志脱敏情况。Release/签名/隐私发布门禁继续属于阶段6，不因这份计划提前关闭。
- 声称“支持Android/iOS和五大厂商”前，给出实际通过的矩阵；未测项写“计划支持，待设备验证”。首个MI9版本通过后也不能宣布全平台完成。

官网核查修正：小米、vivo、荣耀的照片权限规范也约束头像选图用途，OPPO有应用类别权限审核要求。因此“非Google Play”不等于无其他渠道限制。当前仍以自用开发、系统实际授权为范围，保留自定义四列界面；部分授权只展示可访问项，拒绝或能力不可用时由用户选择系统选图退路。不根据商店文本推断MI17侧载包必然被拦截，不绕过系统策略；发布判断后置。

### 4.4 统一权限状态与动作

| 状态 | 文案/页面 | 可用动作 |
|---|---|---|
| 检查中 | “正在检查照片访问权限”，不提前显示旧照片 | 关闭；完成前不重复申请 |
| 未申请 | “允许访问照片后，可在此浏览相册并选择头像” | “授权照片访问”、系统选图、关闭 |
| 完整 | 网格；空时“当前没有可访问的图片” | 分组、拍照、系统选图；不再展示授权按钮 |
| 部分（包括零张） | 网格/部分授权空态；常驻“仅显示已授权的照片” | “管理可访问照片”、系统选图、拍照、关闭；不反复要求升级完整权限 |
| 拒绝但可再次申请 | “尚未获得照片访问权限，可授权后浏览，或使用系统相册选择” | 主动授权重试、系统选图、关闭；不自动重试 |
| 已拒绝且不可再次申请 | “照片访问未开启，可前往设置调整” | 前往设置、系统选图、关闭；设置返回只检查 |
| 系统受限 | “照片访问受到系统限制” | 系统选图（宿主可用时）、关闭；不承诺设置可解除家长/组织限制 |
| 能力/检查错误 | “暂时无法读取照片访问状态” | 重试检查、系统选图、关闭；不把异常当成空库/拒绝 |

Android是否可再次申请结合实际请求结果/平台信号判断，不能仅凭首次`shouldShowRequestPermissionRationale=false`认定永久拒绝；未知时不展示保证可用的设置修复承诺。iOS denied不重复request，restricted不循环引导解除限制。

iOS宿主配置`PHPhotoLibraryPreventAutomaticLimitedAccessAlert=true`，关闭自动有限访问提醒；本包只在点击“管理可访问照片”时主动呈现管理界面。该Info.plist配置影响整个宿主，README必须说明，不能由包暗中覆盖其他模块策略；WanAndroid按本稿配置。Android34+管理访问采用受支持的重新选择流程；能力不可用时使用公开设置入口及说明，不伪造管理弹层。相关依据见[插件有限访问说明](https://pub.dev/packages/photo_manager#limited-entities-access-on-ios)。

授权请求单飞。系统弹层引发的短暂inactive不算用户离开；回到resumed后先检查真实结果再查询。真实进入后台按§5.4处理。未同意、拒绝和受限状态都允许退出，不能先请求权限才允许系统选图。

## 5. 性能、资源与失败

- 默认每页80张，临近末尾加载下一页；只预取可见区域及前后一屏缩略图，不加载整库原图。§3.2元数据索引与图片字节预取分开。
- 缩略图按格宽和DPR请求尺寸；并发上限4，组件持有的解码缩略图LRU预算24MiB。此数不代表Flutter、原生、OS及解码器总内存，分别测量，不能用一个Dart计数宣称总内存受限。
- 分页按ID去重；变化后重建查询版本，不能把页码当稳定身份。追加失败保留当前内容，页尾重试；连续两页无新增停止自动追加并允许刷新。
- 单格失败局部重试，封面失败用占位；首屏失败与追加失败分别反馈。云端占位不是损坏图片错误。
- 取消、失败、退出、切号始终保持原头像。浏览状态只存当前会话，不新增数据库/偏好；进程终止后从所有图片重进，不伪造恢复旧选择成功。

### 5.1 双端静态导出契约

本期统一返回“当前可访问版本的、方向已应用到像素的静态PNG”，不返回未定义的原始文件。归一处理由包完成，宿主仍独立校验结果。约定如下：

这是本修订新增的导出取舍：优先让不同Flutter宿主收到一致的可处理图片，同时会失去原格式、动画、源元数据及HDR信息，PNG也可能增大文件。本期不提供“保留原图”开关；后续若有无损归档/原格式传输需求，须另定导出契约，不能复用此结果却宣称无损原图。

| 项目 | 确定规则 |
|---|---|
| 版本 | iOS使用PhotoKit当前已编辑版本，包含平台公开的裁切、旋转和调色；Android使用当前MediaStore资源URI公开的内容。厂商图库只在私有数据库保存的非破坏编辑不保证可读，不冒充与厂商App画面一致 |
| 缩略图一致性 | 请求同一当前版本；点选后记录资源修订，移交前再检查。期间变更则取消本次准备，刷新并提示“照片已变化，请重新选择”；不得悄悄改取未编辑原图 |
| 普通静态图 | 首版处理JPEG/PNG/HEIC/HEIF；平台无法解码时返回unsupportedFormat。其他格式不作成功承诺，不盲目按扩展名处理 |
| GIF | 使用当前版本的第一个显示帧（索引0），按逻辑画布合成，尊重透明背景与帧偏移；不以缩略图代替，不寻找所谓最佳帧。若当前版本已被平台渲染为静态图，使用该静态结果 |
| Live Photo/动态照片 | iOS取PhotoKit当前版本提供的关键静态照片/封面，包含平台已公开的关键照片调整；不从视频任意截帧、不下载或返回配对视频。无法取得所需静态版本时报错。Android只处理公开的静态封面部分，不解析厂商私有动态格式 |
| 格式/方向/尺寸 | 输出8位sRGB静态PNG（image/png），保留透明通道；EXIF的旋转和镜像只应用一次到像素，输出方向为upright。不为通过预算静默缩小/裁切；尺寸为当前版本归一后的实际像素宽高，不沿用过期原图宽高 |
| 元数据/色彩 | 包去除EXIF、GPS、XMP/IPTC、拍摄时间、设备/作者等源元数据；只保留解码PNG必需信息及标准sRGB色彩声明。宽色域/HDR需转为SDR sRGB，不能仅改标签；暂不保证跨设备色彩逐像素相同，能力不足则明确失败 |
| 文件完整性 | 包自有目录中先写.partial，关闭并核验签名、真实尺寸、字节数、方向约定后再原子重命名为完成文件；损坏/零字节/预算超限不产生selected |
| 对外描述 | 租约包含不可变文件描述：导出契约版本、MIME、实际byteLength、pixelWidth/Height、upright、metadataPolicy=stripped、staticKind。路径只指向包自有副本；不向宿主提供源URI、相册路径或插件对象 |

iOS的current/original有不同语义；具体原生读取路线须在依赖验证中证明当前版本、静态画面及预算均成立，不能仅因某getter名为file就假定符合。[Apple版本说明](https://developer.apple.com/documentation/photos/phimagerequestoptionsversion)、[已有编辑的渲染结果说明](https://developer.apple.com/documentation/photos/phcontenteditinginputrequestoptions/canhandleadjustmentdata)提供选型依据，不等于本项目已有实现。若依赖只能返回原图或配对视频，补包内原生网关或明确不支持，不能放宽本契约。

WanAndroid新增导入入口核验文件内容与描述一致、预算和账号代次，复制为自有候选后释放租约；这条入口不再执行第二次EXIF旋转。现有相机/系统选择器输入仍走既有归一流程；裁切及最终512×512头像输出保持原契约。

### 5.2 缓存归属、权限缩小与租约

| 层 | 所有者/使用规则 | 撤权、关闭与清理 |
|---|---|---|
| 元数据及查询 | 包会话；key含sessionId、权限代次、库修订 | 缩小权限先清展示快照/失效请求，重新查询；退出释放，不持久化 |
| Flutter缩略图 | 包LRU及带命名空间的ImageProvider key；key另含资源ID、修订和尺寸 | 删除对应条目并定向evict Flutter imageCache中的本包key，释放当前ImageStream/可见图片；禁止全局imageCache.clear |
| 原生缩略图预取 | 包会话专用请求/缓存对象 | 取消请求、停止本会话预取；优先只用内存缓存。若底层共享缓存不能按拥有者清理，禁用其磁盘写入或替换该路径，不能把stopCaching等同于物理删除所有系统缓存 |
| 插件磁盘中间件 | 必须先查明锁定版本每个getter的实际文件归属 | 未证明按资源/会话清理安全前，不调用会生成共享磁盘缓存的file/originFile等导出捷径。不删除插件返回的未知路径，不调用全局clearFileCache |
| 包自有暂存/完成文件 | 随机会话目录下的.partials和租约文件，排除系统备份 | 移交前取消/失败由包删除；移交后由宿主finally调用幂等release；释放只能作用于该租约目录 |
| 宿主候选 | AvatarRepository | 复制接纳后独立管理，按头像账号代次/取消/持久化原规则处理 |
| 系统图库/iCloud/媒体提供方缓存 | 操作系统/提供方 | 不擅自删除、不承诺可擦除；撤权后不再读取/显示。OS拥有的副本不能计入包已清理证明 |

权限缩小或撤回时先隐藏旧内容，推进permissionEpoch并取消准备，再处理上述包拥有的缓存；迟到解码/下载回调只释放本次资源，不重新放入任何缓存。无法得知精确缩小范围时保守失效本会话全部图像。不能以仅替换Dart map或更换cache key代替释放旧条目。

插件文档明确部分Android/iOS文件getter会产生缓存，`isLocallyAvailable`也不等于已有可安全借用文件；故“租约释放”不能自动代表插件副本已经释放。[插件缓存机制](https://pub.dev/packages/photo_manager#cache-mechanism)。依赖验证必须给出调用清单：具体版本/方法、是否写盘、目录归属、并发共享、单资源清理、网络开关、原生取消、失败遗留及实测磁盘增量。用宿主哨兵文件和两个同时活跃会话证明不误删其他业务。不能满足的getter退出调用链，采用包内可控原生读取/导出；不把风险留给README免责。

每会话导出单飞，成功返回前文件属于包。协调器原子移交selected时租约所有权转给宿主；页面dispose不删除已移交文件，宿主在导入成功、失败、切号或导航取消的finally中release。release失败不伪称清理成功，记录脱敏cleanupFailed并入自有目录后续清扫；不泄露路径。

正常失败立即清理自有partial和未移交成品；异常终止遗留目录在后续初始化清理：无有效活跃租约且距最后活动超过24小时才删除。本进程活跃租约排除清扫；跨进程重启不恢复上次租约。宿主须及时复制/释放，不将租约当永久路径。安全检查限定自有目录、拒绝符号链接越界；禁止日志包含原图、URI、路径、账号或源图片元数据。

### 5.3 分阶段预算与磁盘失败

默认值是需求中的安全边界，并非性能测量结论；1MiB=1024×1024字节。通用包与宿主分别配置，宿主必须显式传入自身预算；不能等返回后才执行宿主限制。

| 预算 | 通用包默认 | WanAndroid头像 | 约束对象 |
|---|---|---|---|
| 输入编码字节 | 32MiB | 32MiB | 本次读取的当前图片表示，非整份Live Photo视频+照片，也非无关原始版本 |
| 完成PNG字节 | 64MiB | 32MiB | 归一后实际文件；小HEIC转PNG仍可能失败 |
| 单边/总像素 | 8192 / 1600万 | 8192 / 1600万 | 当前表示完整解码前及最终归一图两次校验；任一超限拒绝 |
| 准备耗时 | 60秒，可配置 | 60秒 | 从启动读取至完成移交前；包括下载/解码/写入，不含用户阅读下载确认框 |
| 导出并发 | 每会话1；默认进程导出调度上限1 | 同左 | 排队可取消；从实际开始准备计超时，不让多会话同时持有多张全尺寸位图 |
| 取消后停止等待 | 最长5秒 | 最长5秒 | 从取消/准备超时发生时计，不从再次选图重置；不影响立即返回网格 |

执行顺序必须可故障注入验证：

1. 点选后先复核权限/身份/资源修订，读取可用的当前表示尺寸、类型和长度。已知超限立即拒绝，不触发完整下载。元数据未知不当作0或合格；不借用未编辑原图尺寸冒充当前尺寸。
2. 当前表示未知尺寸时先获取有界头部/文件信息；完整像素解码之前必须得到可靠宽高并作溢出安全的总像素检查。无法以受限资源识别格式/尺寸，明确失败，不退回无界decode。元数据值与实际头部不一致以实际为准并重新校验。
3. 输入以流或文件句柄分块读取，应用拥有的暂存写入在字节上限处中止；不能先无界readAsBytes/下载完整文件后才查大小。流中途发现超限即取消、关句柄、删除partial。解码在平台工作线程执行，不通过Dart跨通道传整张大位图；同时存在的全尺寸缓冲区必须记录并测峰值。
4. PNG编码使用可计数且可中止的输出，边写边限制输出字节；输出超限、磁盘不足、写入中断或编码失败都不返回租约。不能先把整份PNG放入内存再判断。写前对包目录做可用空间检查（输入上限+输出上限+8MiB余量），检查只是提前反馈，仍须处理写入时ENOSPC/IO错误。
5. 成品头部、字节数及导出描述再次校验，关闭句柄后原子重命名；移交前复核权限/修订/取消。宿主导入复制也有自己的字节限制和失败清理，不信任描述代替文件内容校验。

**边界必须如实描述**：OS/图库提供方可能自行下载、转码或缓存，包不能保证系统层实际网络流量/内存永不超过预算。所选API若先返回完整Data、先下载到不可控插件缓存才允许检查，就不满足上述应用侧有界读取要求，必须更换适配路径或返回能力不支持并保留系统选图入口。依赖验证应证明iOS当前编辑表示、云端静态图和Android URI这三类路径；不得把PhotoKit分块回调等同于系统内部传输可严格限额。网络、当前版本与有界导出无法同时满足时，不静默回退原图或绕开上限，记录明确能力缺口。

### 5.4 联网、后台和超时

- 浏览/滚动/封面预取默认不允许本组件发起云端完整资源下载；缩略图只取本地/系统已有缓存。无本地缩略图时显示云端占位，仍可点选；普通重试不改变网络策略。不能先下载原图来生成网格缩略图。
- 点选仅云端或本地尝试返回需要网络的资源，先显示“需要下载此照片，可能使用移动数据”；只有用户点击“下载并使用”后才允许该次请求联网，Wi-Fi/移动数据均可。不同照片和失败后的重试重新确认，不持久保存联网同意。平台无法判断本地性时先用禁止网络的请求探测，不能用联网读取探测。
- 本地请求不因断网失败；需要联网时展示真实平台进度，无进度就不定进度。离线/下载失败留在原分组和位置，提示“照片尚未下载，连接网络后可重试”，由用户再次发起；不增加网络状态插件或保证仅凭网络连通就能获取资源。
- 真实进入后台（paused/hidden；平台映射需验证）取消未移交准备和网络授权，原生支持时停止下载；恢复前台重查权限/资源，显示“准备已取消，请重新选择”，不自动续传。短暂inactive（如权限系统弹层）只收起面板，不错误地当成完整后台切换。
- 60秒用单调时钟计算，不能在暂停/恢复时重置；若回调在后台取消通知前后迟到，接纳前同时检查生命周期、超时和操作版本。OS可能继续内部下载，组件拒收且不展示其迟到结果。
- 操作系统在包之外自行同步相册不受此开关控制。验收断言的是组件请求参数和调用链不主动允许联网，不宣称整部手机在浏览期间没有网络流量。
- 宿主接管系统相机/系统选择器后使用原有外部流程；第三方提供方自己的联网行为不受本包云端开关控制，不能把此处策略冒充对所有系统图库的保证。

取消或超时后的调度补充：立即失效旧token并恢复网格，不await底层结束才响应返回。自取消/超时起最多等待5秒确认旧应用侧任务停止；期间再次选图显示“正在结束上次处理”，只等剩余时间，不重新计时或累计排队。到期仍未释放则结束本次等待，提示“图片处理暂不可用，请使用系统相册选择或稍后重试”，错误码为exportUnavailable；允许浏览、系统选图和退出，不能无限转圈。未确认安全停止前后续自定义导出立即给出同样提示，重开页面也不重置进程级故障状态；旧任务确已释放后才允许用户重新发起，不自动重放先前选择。不能仅释放锁就另起同类工作，导致卡住的解码任务无限累积；旧任务仍持有的文件保持隔离，实际停止后再清理，迟到成功不得移交。技术验证用“永不完成/取消不返回”的Fake证明5秒内出现明确失败，再证明迟到停止可恢复且无双任务/双终态。

## 6. 可移植方案

### 6.1 交付形态

在当前唯一可写项目内建立`packages/album_picker/`，作为独立Flutter package，通过path依赖接入WanAndroid。当前不创建外部仓库、不初始化Git、不发布pub.dev；确认后可整体复制到其他Flutter仓库或以Git/path/pub依赖分发。

单个package内分UI、ViewModel、纯Dart契约/模型、Repository实现及平台适配层；先不拆多个联邦插件。候选底层依赖`photo_manager`，只承担已验证的权限/元数据/缩略图能力；有界当前版本导出、定向缓存清理若依赖无法满足，落在本包Android/iOS原生网关。仍是一个可移植包（含插件平台实现），不把补丁塞进WanAndroid的Activity/AppDelegate再宣称包独立。版本、许可证、实际调用缓存行为及双端构建兼容性在依赖验证中检查并锁定，不能把检索到的版本当成已通过门禁。

计划结构（仅规划，未创建源码）：

```text
packages/album_picker/
  lib/album_picker.dart        # 稳定公开 API，不导出 photo_manager 类型
  lib/src/model/              # Album、AssetRef、PermissionState、结果
  lib/src/data/               # 契约、仓储、平台网关、临时文件导出
  lib/src/features/picker/    # state、view_model、view、component
  lib/src/bootstrap/          # 默认实现装配；View不创建平台服务
  android/ / ios/             # 需要时承载包自己的受控导出/缓存平台实现
  example/                   # 无 WanAndroid 依赖的最小宿主
  test/                      # Fake、Widget、契约测试
  integration_test/          # 受控平台验证
  README.md / CHANGELOG.md
```

### 6.2 公开边界

- 核心输入：主题、本地化文案、拍照/系统选图能力、图片处理预算、取消信号；其余可配置值见§1。首版固定四列和单选，不预建未使用的多选/视频抽象。
- 展示入口提供可嵌入页面及标准导航便利封装，不要求宿主使用特定路由框架。状态实现留在包内部，不要求宿主使用 Riverpod，不向外暴露 Provider 或插件实体。
- 结果为可区分的`selected(文件租约与§5.1描述)`、`cancelled`、`cameraRequested`、`systemPickerRequested`、`failed(脱敏错误码)`；普通读取/导出错误在页内恢复浏览，仅组件无法继续时返回failed。同一选择会话至多一个终态结果；同会话可有多次失败/取消的选择尝试，每次使用新selectionToken。
- 点击拍照格或系统选图入口：关闭本选择会话并返回对应意图，由宿主 ViewModel 调用现有系统能力。相机取消后本项目回头像查看页，与既有契约一致；首版不增加“拍完仍回网格”的另一套恢复逻辑。
- 所选图片最终返回前完成文件准备；纯 Dart 结果不向宿主泄露 AssetEntity、PHAsset、ContentResolver、BuildContext 等实现类型。
- 包内不依赖 WanAndroid 的 AuthState、AvatarRepository、主题源码、接口地址或路径；所有资源、文案、默认主题在包内自足，宿主通过参数覆盖。
- 页面退出后取消查询并释放监听；多次打开相互隔离，每个选择会话拥有独立 sessionId，底层进程级监听采用引用计数，不能关闭其他调用方的监听。

### 6.3 WanAndroid 接入

头像查看页 → 本 Feature ViewModel 发起带账号身份的选图操作 → Navigation 只展示组件 → 返回结果交回 ViewModel → AvatarRepository 接纳候选 → 现有头像调整页 → 原子提交头像。

宿主发起时捕获 `userId + accountVersionKey + operationToken`；账号失效、切号、路由关闭时主动取消组件会话，结果返回及每个导入异步边界再复核身份。组件只认识不透明取消信号，不保存账号。

AvatarRepository继续作为头像候选和持久化唯一权威。新增“从组件文件租约导入候选”的生产入口，复用文件预算校验、候选、裁切和提交；包的upright PNG按§5.1验证后复制，不重复EXIF归一。旧相机/系统选图仍用原归一器。租约通过数据适配层转换为项目纯契约，不能把插件类型暴露给Feature。

现有相机/系统选择器及 Android lost-data 恢复继续使用原 pending 记录；自定义网格不建立外部选择器 pending，也不调用 retrieveLostData 恢复网格。包导出临时文件在宿主复制后 release；宿主候选生命周期保持原规则。

### 6.4 移植验收

不是仅把代码放到 packages 就算可移植。必须能在项目内的独立最小示例中，仅声明该包依赖并完成平台配置后运行；无需复制 WanAndroid 的 lib、Provider、主题、路由、账号模型或业务文件。

README须包含 Android/iOS 权限配置、最低版本、主题/文案覆盖、结果与租约释放、取消、系统相机/选图意图接入、错误、云端限制、发布策略和完整调用例。包内 analyze/test 与示例构建须显式纳入门禁；根 flutter test 不会自动代表嵌套包测试。

组件使用的最低系统以本项目 Android API24/iOS15 为首个支持承诺；更低版本不凭插件声明认定兼容。许可证选择和公开发布属后续独立决定，不自动公开源码。

### 6.5 状态转换、取消和移交边界

| 当前状态 | 事件 | 下一状态/页面行为 | 文件/结果责任 |
|---|---|---|---|
| 检查权限 | 未授予/完整/部分/检查失败 | §4.4对应页；完整/部分进入查询，不触发隐式申请 | 无选择结果 |
| 说明页 | 点击授权/管理/设置 | 单飞系统操作，返回后重新检查；弹层取消留说明页/原网格 | 不自动转系统选图 |
| 浏览 | 开关分组/切相册 | 下拉或新分组查询；保留各组锚点 | 查询代次隔离 |
| 下拉 | 返回/点遮罩/点当前组 | 收起，留网格 | 无终态；关闭X则退出 |
| 浏览 | 点照片 | 收起下拉，锁定selectionToken；本地预检/必要时等待下载确认 | 禁止换组、选其他图、拍照、管理授权、系统选图 |
| 等待下载确认 | 取消/系统返回 | 取消本次尝试，恢复原分组和位置 | 不下载，不结束选择会话；X/宿主取消则退出 |
| 准备文件 | 重复点图/换组/其他入口 | 操作不可用且无隐藏命中；显示进度和“取消准备” | 不排队第二次选择 |
| 准备文件 | 系统返回/取消准备 | 立即使token失效，回原网格；若再次返回则退出页面 | 清理不阻塞返回；旧任务释放最多等5秒，超时按§5.4明确失败，不无限等待 |
| 准备文件 | 失败/超时/损坏/超预算/磁盘不足 | 原分组和位置内显示具体可操作错误，可另选或重试 | 本次尝试结束，包清理；不产生selected，不改头像 |
| 准备文件 | 权限变更/图片变更或删除 | 取消准备，重查权限/库；必要时回说明页/所有图片并提示 | 旧token及结果无效 |
| 等待确认/准备 | 真正进入后台 | 取消尝试；恢复时重查并留网格/对应权限页 | 不自动继续；规则见§5.4 |
| 任一未终态 | X关闭/宿主取消/页面移除 | 退出选择器，发一次cancelled | 取消请求，包清理；dispose兜底，不二次发结果 |
| 浏览/说明页 | 拍照/系统选图 | 退出并发cameraRequested/systemPickerRequested | 宿主接管旧流程；外部取消回头像查看页 |
| 准备完成待移交 | 全部校验通过，协调器接受完成 | 原子进入terminal(selected)，关闭选择器 | 租约所有权同一原子步骤移交宿主；不得先发结果后改所有权 |
| 宿主导入 | 复制/校验失败 | 在仍有效的头像查看页显示导入失败，可重新打开选图；不恢复旧网格 | finally释放租约，原头像保留；失效账号不展示旧错误 |
| 宿主导入 | 成功且身份有效 | 导航现有头像调整页 | 宿主候选权威接管，租约释放 |
| 裁切 | 取消/确认 | 取消回头像查看页；确认按现有原子保存规则 | 取消清候选且原头像不变；不返回旧相册位置 |

完成边界为单一串行协调器中的终态提交。取消先被处理则token失效，即使导出已落盘也不得移交；完成先被处理则只返回selected，后续取消由宿主再次检查账号/操作身份并拒绝或释放，不能追加cancelled。没有按毫秒时间戳猜测“同时”的分支。每个异步结果携带sessionId/permissionEpoch/libraryRevision/selectionToken，移交前核对；终态后所有迟到回调仅执行自己拥有的资源清理。

权限缩小与旧终态也按此界限处理：尚未移交一律取消；已移交的应用副本已归宿主，不能由包越界删除。宿主取消/切号仍保证不接纳、不持久化旧结果并释放自己的候选；不声称OS撤权可以自动收回此前合法导出的所有应用副本。

相册关闭与宿主接收必须由展示入口统一协调，导航Future未送达、展示入口销毁等异常也要保证租约最终有唯一接收者或被释放；不能先将租约标为交付后让结果无人接收。以受控竞态验证该边界，不只测试正常await。

## 7. 验证与实施顺序

### 7.1 性能基线与可执行验收

- 数据集固定为100、1000、10000张受控虚构图片，最多20组，含同名/长名组、不同时间及相同时间跨页边界；各规模使用固定比例的1/4/12MP图片，另列超预算、损坏、GIF、HEIC/方向样本。保存生成种子、文件哈希、分组/时间清单；不使用真实私人相册当基准，不未经授权向个人图库批量灌数据。
- MI9作为首个性能基线；MI17记录同用例对照。固定包/宿主版本、系统/API、刷新率、字体/DPR、构建模式、温度状态、授权范围和数据集。使用profile观测Flutter帧/内存，设备发布构建性能后续再单列，debug耗时不冒充发布性能。
- 每规模冷启动5次：新进程、空组件缓存、预先授予相同权限；不清系统图库/其他模块缓存，因此命名为“组件冷启动”，不声称OS磁盘缓存冷。记录从页面进入到首个完整可见屏幕的本地缩略图就绪时间（相机格不计），并单列元数据索引/数量完成耗时；系统授权弹窗时间另记。
- 每规模按固定滚动脚本连续快速上下滑动60秒，再重复开关选择器10次；记录首屏各次值/中位数/最大值、帧时间与超过设备单帧预算的比例、Dart堆/原生内存/RSS峰值与关闭30秒后的值。不能把Flutter imageCache数值当进程内存。
- 磁盘记录打开前、只浏览后、导出中、成功release后、取消/超时/模拟磁盘不足后及异常重启清扫后的包目录和插件缓存增量；不得导出真实文件名/元数据。仅浏览不应产生本组件原图缓存；正常释放后本会话自有副本归零，清理失败必须可重试且可观察，不能标为清理通过。
- 无需等设备即可判定的门槛：固定四列、分页80/并发≤4/组件LRU≤24MiB、导出预算前置、无源图误删、无旧授权图复现、无双终态、无未经确认的网络请求；用Fake计数、受控字节流及Widget/平台测试验证。总进程内存和帧率不能仅凭这些门槛判为通过。
- 首屏耗时/掉帧/内存绝对阈值暂不凭空定数。实施时先提交MI9上述原始统计并确定数值，再按相同条件复测；这项基线未做时只标“性能待测”，不能宣称流畅度验收完成。无法取得云端/其他厂商/iOS真机证据继续后置，不扩大本轮设备范围。
