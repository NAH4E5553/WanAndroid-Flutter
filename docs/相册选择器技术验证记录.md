## 2. 为什么没有引入photo_manager

实际核查官方发布的photo_manager3.12.0源码：iOS PMManager当前图片路径存在`requestImageDataAndOrientation`接收完整NSData再落盘的分支；Android ScopedCache存在无上限copyTo和共享缓存目录清理。页面返回一个Future并不保证调用前已限制输入、输出和缓存归属。因此不把这些文件getter放入生产链路，也不添加该插件依赖。采用开工单预留的原生网关路线，不降低产品契约。

Android直接查询MediaStore图片及挂载卷，API24–32旧读取权限、33图片读取、34+部分照片权限；不申请定位、视频、音频或全文件管理权限。iOS使用PhotoKit的readWrite完整/有限授权，主动管理有限照片，资源读取优先fullSizePhoto；有调整记录但没有公开渲染结果时明确失败，不回退原始照片。

参考：[插件官方说明](https://pub.dev/packages/photo_manager)、[Apple fullSizePhoto定义](https://developer.apple.com/documentation/photos/phassetresourcetype/fullsizephoto)。厂商证据继续以[官网核查记录](相册选择器厂商官方适配核查.md)为准。

## 3. 导出、缓存与取消

- 元数据可得时预检查；应用侧流式写入先计数后写，完整解码前检查文件头及像素，生成upright、静态sRGB PNG，复核尺寸及资源修订后移交。默认输入32MiB/输出64MiB，头像输出32MiB，8192边长/1600万像素。OS内部下载、系统缓存和峰值内存不在这些字节计数的保证内。
- iOS ImageIO探针发现即使从新CGImage编码，仍会生成eXIf块；现采用PNG块流过滤，只保留像素及颜色解释所需块，去除EXIF/GPS/文本元数据。Android通过新的sRGB Bitmap输出，不携带源元数据。
- 浏览缩略图不启用网络，原图只在用户选中后准备；需要联网的PhotoKit资源先提示确认。Android不接厂商私有云账号，只处理公开MediaStore资源。
- 所有应用导出副本均在包自有私有缓存目录。释放幂等，失败返回cleanupFailed并输出不含路径的错误码，下次创建会话重试未完成清理；异常退出残留超过24小时后清扫。Android清扫拒绝符号链接；不会递归清其他插件缓存。权限/库变化定向清理本会话缩略图及Flutter ImageProvider，迟到数据不入缓存。
- 60秒超时；取消立即恢复网格。进程级调度器保留实际工作占用，取消起5秒未安全结束则明确exportUnavailable，重选不重置期限，不创建无限并行任务。旧任务最终结束才恢复导出；迟到成品释放。
- iOS隐私资源已配置文件时间戳、单调计时及磁盘容量的使用理由，分别用于自有缓存、超时和导出前空间检查。对应[Apple required-reason API说明](https://developer.apple.com/documentation/bundleresources/app-privacy-configuration/nsprivacyaccessedapitypes/nsprivacyaccessedapitype)；这不替代完整发布审核。
